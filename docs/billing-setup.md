# 月額型サービス（モバイルメニュー・サロン予約）の申し込み・課金のしくみ

飲食店・サロン向けは「人の手をかけずに回る」ことを目標にしています。
サーバーを持たず、Stripe の標準機能と GitHub Actions だけで動く構成です。

## 全体の流れ

| 段階 | しくみ | 人の作業 |
|---|---|---|
| 申し込み・最終確認 | `start/index.html`（特商法の最終確認画面を兼ねる） | なし |
| カード登録・30日無料 | Stripe の Payment Link（無料お試し30日） | なし |
| 申し込み完了 | `start/thanks.html` に自動で戻る | なし |
| 運営者への通知 | 毎朝、前日の新規申し込みをメールでまとめて通知 | 管理画面のご案内を送る（※） |
| 課金7日前のお知らせ | Stripe の自動メール | なし |
| 課金前日のお知らせ | GitHub Actions（`scripts/billing-daily.mjs`） | なし |
| 31日目からの課金・領収書 | Stripe の定期課金 | なし |
| 支払い失敗の連絡・再請求 | Stripe の自動メール・自動再試行 | なし |
| カード変更・解約 | Stripe のカスタマーポータル（`account/`） | なし |

※ 管理画面（本番アプリ）ができたら、ここも Stripe の Webhook で自動化します。

## 1. Stripe の設定

最初は必ず **テストモード** で作り、テスト用カードで一連の流れを確認してから本番に切り替えます。

### 商品と価格
- 商品「モバイルメニュー」：月額 1,980円（継続・毎月）
- 商品「サロン予約」：月額 1,980円（継続・毎月）
- 商品「モバイルメニュー LINE版」：月額 1,980円（継続・毎月）
- 商品「サロン予約 LINE版」：月額 1,980円（継続・毎月）
- 商品「モバイルメニュー Web＋LINEセット」：月額 2,980円（継続・毎月）
- 商品「サロン予約 Web＋LINEセット」：月額 2,980円（継続・毎月）
- 商品「おまかせ設定」：9,800円（1回限り）
- 税込・税別の扱いを決め、LP・特商法・Stripe の表示をそろえます。

### Payment Link（12本）
サービス（モバイルメニュー／サロン予約）× 使う場所（Web版／LINE版／両方）× 始め方（セルフ／おまかせ）。

| 使う場所 | 始め方 | 中身 |
|---|---|---|
| Web版 | セルフ | Web版 月額1,980円 |
| Web版 | おまかせ | Web版 月額1,980円 ＋ おまかせ設定9,800円 |
| LINE版 | セルフ | LINE版 月額1,980円 |
| LINE版 | おまかせ | LINE版 月額1,980円 ＋ おまかせ設定9,800円 |
| 両方 | セルフ | Web＋LINEセット 月額2,980円 |
| 両方 | おまかせ | Web＋LINEセット 月額2,980円 ＋ おまかせ設定9,800円 |

「両方」は、セット商品（月額2,980円）1つで作ります。あとからWeb版→セットに切り替えるときは、カスタマーポータルの「プランの変更」でセット商品を選べるようにしておきます（差額は日割りで調整されます）。
LINEの申請・審査の代行は Payment Link ではなく、お見積もりのうえ個別に請求します。

各リンクの設定：
- 「無料トライアルを追加」→ **30日**
- 支払い方法の収集 → **常に収集する**（カード登録を必須にする）
- カスタムフィールド → 「店名」（テキスト・必須）
- 支払い後の動作 → 「確認ページを表示しない」で、次のURLへリダイレクト
  - `https://knotscheme.github.io/sakuapp/start/thanks.html?s=menu&c=web&p=self`
  - （`s` は menu / salon、`c` は web / line / both、`p` は self / omakase をリンクごとに変える）
- 利用規約への同意 → オン（利用規約のURLを登録）
- 1回限りの商品（おまかせ設定）がお試し中も申し込み時に請求されることを、テストモードで確認します。

### メール（設定 → Billing → サブスクリプションとメール）
- 無料トライアル終了の **7日前** にリマインダーを送る → オン
- 成功した支払いの領収書 → オン
- 支払い失敗時の通知・カード更新の案内 → オン
- 支払い失敗時の再試行（スマートリトライ）→ オン。すべて失敗したらサブスクリプションをキャンセル

### カスタマーポータル（設定 → Billing → カスタマーポータル）
- 支払い方法の更新、請求書の履歴 → オン
- サブスクリプションのキャンセル → オン、**請求期間の終了時にキャンセル**
- 「ログインリンク」を有効にして、そのURLを控えます

## 2. サイトの設定（`start/config.js`）

```js
OPEN: true,
LINKS: {
  menu: {
    web:  { self: "https://buy.stripe.com/...", omakase: "https://buy.stripe.com/..." },
    line: { self: "https://buy.stripe.com/...", omakase: "https://buy.stripe.com/..." },
    both: { self: "https://buy.stripe.com/...", omakase: "https://buy.stripe.com/..." }
  },
  salon: { /* menu と同じ形 */ }
},
PORTAL_URL: "https://billing.stripe.com/p/login/..."
```

`OPEN: false` のあいだは、申し込み画面は見られますが、ボタンは押せません（受付前の表示になります）。

## 3. 毎日の自動処理（GitHub Actions）

`.github/workflows/billing-daily.yml` が毎朝9:07（日本時間）に `scripts/billing-daily.mjs` を動かします。

- 無料お試しが36時間以内に終わるお客様へ、前日のお知らせメール（1人1回。送信済みは Stripe に記録）
- 解約手続き済みのお客様には送りません
- 前日の新しいお申し込みを、運営者へまとめて通知（同じメールアドレスで過去に登録がある場合は「お試し2回目の可能性」と表示）

リポジトリの Settings → Secrets and variables → Actions に登録します。

| 名前 | 中身 |
|---|---|
| `STRIPE_SECRET_KEY` | Stripe の制限付きキー（Subscriptions・Checkout Sessions・Customers の読み取り、Subscriptions の書き込み） |
| `RESEND_API_KEY` | メール送信サービス Resend の APIキー（独自ドメインの送信設定が必要） |
| `MAIL_FROM` | 送信元。例：`サクアプ <billing@example.com>` |
| `OWNER_EMAIL` | 新規申し込みの通知を受け取るアドレス |

Secrets が未設定のあいだは、何もせずに終了します。
Actions タブの「Run workflow」から手動で動かすと、初期値はメールを送らない試運転（DRY_RUN）です。

## 4. 正式受付を始めるときのチェックリスト

- [ ] テストモードで、4本すべての申し込み → 完了ページ → ポータルで解約、を確認した
- [ ] 本番の Payment Link とポータルのURLを `start/config.js` に入れ、`OPEN: true` にした
- [ ] LP（`menu/` と `salon/`）の主なボタンを「30日間 無料で試す」（`../start/?s=menu` など）に変えた
- [ ] LP の「正式受付は2027年6月ごろから」の文言を消した
- [ ] 税込・税別の表示を、LP・申し込み画面・特商法・Stripe でそろえた
- [ ] 利用規約・特商法の最新版を確認した
- [ ] GitHub の Secrets を登録し、手動の試運転でログを確認した

## 費用の目安

- Stripe：決済ごとの手数料のみ（月額費用なし）
- GitHub Actions：公開リポジトリは無料。非公開でも1日1回・1分程度なので無料枠に収まります
- Resend：無料枠（1日100通・月3,000通）で、当面は収まる見込みです
